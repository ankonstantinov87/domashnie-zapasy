# Домашние запасы — подключение общей Google Таблицы

## Текущее состояние
- Мобильное приложение и десктопная версия остаются на прежнем GitHub Pages.
- Данные продолжают храниться локально до первого успешного подключения.
- Общая Google Таблица уже создана в приватной папке Google Диска «ChatGPT → Домашние запасы».
- Синхронизация не запускается без URL вашего Apps Script и секретного ключа.

## Однократная настройка владельцем
1. Откройте общую Google Таблицу из папки «Домашние запасы».
2. Выберите «Расширения» → «Apps Script». Это привязанный к таблице проект.
3. Скопируйте содержание `cloud/Code.gs` из этого репозитория в редактор Apps Script (замените стартовый `myFunction`), сохраните.
4. В выпадающем списке функций выберите `setupPantrySync` и запустите один раз. Google запросит разрешение на работу с этой таблицей.
5. В «Журнале выполнения» получите секретный ключ. Он **не должен попасть в GitHub, чат, скриншоты или общие документы**.
6. «Развернуть» → «Новое развертывание» → «Веб-приложение» → «Выполнять от имени: я» → «Кто имеет доступ: все» → «Развернуть».
7. Скопируйте адрес веб-приложения `https://script.google.com/macros/s/.../exec`.
8. На компьютере в приложении «Домашние запасы» выберите «Ещё» → «Подключить облако». Введите URL и секретный ключ. **При этом данные не выгружаются автоматически.**
9. Создайте JSON-копию. Нажмите «Первый перенос этой базы» только на одном основном устройстве, если облако пустое. После этого «Синхронизировать».
10. На втором устройстве не нажимайте «Первый перенос», если там тоже есть отдельные данные. Перед объединением создайте JSON-копию и согласуйте расхождения.

## Безопасность
- Таблица и папки Диска не должны быть опубликованы всем по ссылке.
- Код и интерфейс могут оставаться в публичном GitHub, семейные данные не записываются туда.
- Секрет синхронизации хранится локально в браузере, не входит в JSON-копию и не передаётся в этот чат.
- Apps Script использует пароль доступа для запросов через браузер; это не полноценный Google OAuth. Токен в GET-запросах проходит по HTTPS, но может появляться в диагностических сетевых журналах, поэтому не используйте тот же пароль для других сервисов.
- При конфликте версий ни локальная, ни облачная база не перезаписываются автоматически.
- Если вы редактируете таблицу вручную или через ChatGPT, перед следующим обновлением приложения нужно увеличить значение `cloudRevision` в листе «Настройки», иначе клиент может не обнаружить внешние изменения.
- Фото чеков ещё не отправляются автоматически. На следующем подэтапе добавим локальную очередь с синхронизацией исходных файлов в приватную папку «Входящие чеки и списки».
- Не удаляйте локальные данные и не отключайте резервные копии до контрольного теста чтения/записи с двух устройств.

## Проверка первого запуска
- Отсутствует интернет: изменения остаются локально.
- Интернет есть, облако доступно: новые изменения отправляются после установленного подключения.
- Устарела облачная ревизия: клиент показывает конфликт вместо потери данных.
- Сервер не подтвердил операцию: повторная попытка использует идентификатор операции и не должна удваивать записи.

## Где искать

`app.js` — прежние карточки товаров, закупки, чеки
