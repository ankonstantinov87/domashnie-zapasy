# Домашние запасы — тестовая версия 0.9

Русскоязычное локальное приложение для Android (PWA). Бесплатно, без регистрации, без рекламы, без сетевой базы и с локальным хранением данных. При поиске по штрихкоду может обращаться к Open Food Facts (только код товара, без остатков).


## Новое в версии 0.2

- Переименование купленного товара прямо из «Запасы»: кнопка ✎ или «Подробнее» → «Переименовать»; остатки, партии и сроки сохраняются, связанные подписи в истории и закупке корректируются.
- «Запасы» → «Сканировать штрихкод / Честный знак»: камера использует BarcodeDetector браузера, если устройство поддерживает формат.
- Распознаются EAN/UPC и, если поддерживается, Data Matrix. Из маркировки Data Matrix извлекается только GTIN; проверка подлинности в системе «Честный знак» не выполняется.
- Название сначала ищется в локальных товарах, затем по GTIN в Open Food Facts при доступном интернете; российские товары могут отсутствовать в каталоге. Результат необходимо подтвердить.
- Если камера или формат не поддерживается, доступен ручной ввод GTIN. Фотоимпорт пока не реализован.
- Схема IndexedDB прежняя (schema 1); существующие товары и резервные копии совместимы. При обновлении PWA возможно повторное открытие приложения.

## Что работает в этой сборке

- Каталог продуктов и бытовых товаров, марки и разновидности отдельными карточками.
- Единица учёта на выбор: упаковки, штуки, кг, г, л, мл. **Открытые упаковки не отслеживаются.**
- Быстрая ревизия фактического количества.
- Несколько партий с разными датами годности и местами хранения.
- Отображение просроченных и близких сроков (3 дня).
- Минимальный и целевой запас; предложения пополнить список покупок.
- Закупки с ручным добавлением и импортом обычного текста, удаление/редактирование.
- Подтверждение фактической покупки (срок, место, сумма в ₽), только после подтверждения запас растёт.
- Списание с причиной, журнал операций и суммы покупок.
- Резервное копирование JSON, восстановление JSON, экспорт CSV.
- Демонстрационные записи только по явной кнопке.

## Не готово (будущие этапы)

- Распознавание фото и скриншотов; варианты замены товара пока только текстовое поле.
- Автоматический справочник условий хранения, перерасчёт срока свежести при перемещении; пока даты вводятся пользователем. **Сроки приложение не выдумывает.**
- Изменение единицы уже созданного товара без миграции остатков (можно выбрать при создании).
- Синхронизация с другим телефоном, фоновые уведомления, автоматическая отправка резервной копии в Drive.
- Поиск цен, интеграция с магазинами, учёт рецептов.

## Как попробовать на Android

Для надёжной работы IndexedDB и установки на главный экран приложение следует открывать с постоянного HTTPS-адреса. Простой файл `index.html` сам по себе не заменяет установленную PWA и может работать с ограничениями.

Вариант без сервера и платной подписки — **GitHub Pages**:

1. Создайте новый репозиторий GitHub (общедоступный — для бесплатного Pages; **не загружайте туда резервные копии**).
2. Загрузите в корень репозитория содержимое этого ZIP (`index.html`, `styles.css`, `app.js`, `scanner.js`, `sw.js`, `manifest.webmanifest`, папку `icons`).
3. В настройках репозитория включите Pages → Deploy from a branch → main → root.
4. Откройте опубликованный HTTPS-адрес на Android в Chrome; через меню Chrome выберите «Добавить на главный экран» / «Установить приложение».
5. Проверьте сценарий: добавить 2 товара, списать упаковку, сформировать закупку, подтвердить покупку, скачать резервную копию и восстановить её на тестовых данных.

На компьютере разработчика можно запустить локальный сервер: `python -m http.server 8000`, открыть `http://localhost:8000/`. Для Android использовать опубликованный HTTPS-адрес.

**Конфиденциальность:** статические файлы приложения могут быть публичными, но база продуктов хранится в браузере вашего устройства. Файл резервной копии содержит список продуктов и историю; храните его в приватной папке Google Drive. Ручное сохранение Drive не является автоматической синхронизацией.

**Важно о безопасности данных:** браузер может потерять локальные данные при очистке сайта, удалении профиля или неисправности телефона. После ревизии обязательно сохраните JSON-копию в Google Drive и проверьте восстановление. Не меняйте адрес размещения без экспорта и импорта базы.

**Принцип учёта:** одна упаковка учитывается единицей до полного использования; открытие не приводит к списанию. Для разных сроков годности создаются партии. Для яблок и других продуктов без маркировки на этапе 0.1 срок можно оставить пустым.

## Проведённые проверки

Формы, логика ревизии, списание, частичная закупка, распознавание текстовых позиций и экспорт/восстановление резервного JSON прошли сценарный браузерный тест **с имитацией IndexedDB**, поскольку тестовое окружение ограничивает навигацию Chromium к локальному адресу. Реальная проверка постоянного хранилища, PWA-установки и резервных файлов на Android ещё требуется.

## Обновления версии 0.3

Приложение проверяет обновления service worker при запуске и возвращении на экран (если интернет доступен). При появлении новой версии страница автоматически перезагружается, когда пользователь не редактирует данные. Во время заполнения формы появляется предложение «Обновить» — его следует нажимать после сохранения. Первое обновление с прежнего механизма может потребовать одного-двух обновлений страницы Chrome. IndexedDB не сбрасывается. Для надёжности регулярно экспортируйте JSON.


## Умный импорт сообщений — v0.4

- Встроенный автономный справочник из 68 распространённых товаров и учёт уже имеющихся названий из домашнего каталога; это не единая облачная база для всех пользователей.
- Импорт распознаёт нумерованные списки, количество посреди строки, распространённые единицы, магазины «Магнит» / «ВкусВилл» / «ВВ».
- Слова из скобок и пожелания «либо / или» сохраняются в поле комментария, а не в названии.
- Перед подтверждением отображаются исходная строка, отредактированное название, количество, магазин, комментарий и несколько необязательных вариантов из каталога.
- Нажатие на подсказку подставляет её в название; «Оставить как есть» возвращает результат автоматического разбора. Никакая подсказка не применяется автоматически.
- Принятые пользователем соответствия запоминаются локально и входят в JSON-копию.
- Комментарий виден в списке покупок и перед подтверждением покупки. Новым товарам автоматически предлагается категория из справочника.
- Редактирование названия уже купленного товара (✎ в разделе «Запасы») теперь также показывает подходящие варианты из каталога.
- Если количество в исходном сообщении отсутствует, предлагается 1 единица с явной пометкой. Перед подтверждением его следует проверить.
- Изменения не требуют миграции IndexedDB: все существующие партии, количества и покупки остаются на устройстве.

Ограничения: справочник локальный и начальный, не содержит всех товарных позиций и брендов. Количество и выбор конкретного продукта (включая вкус, объём и упаковку) требуют проверки человеком. Фотоимпорт пока не реализован.


## Сверка покупок по чеку — тестовая версия 0.7

1. В «Покупках» нажмите «Сверить по чеку». Поддерживаются фото / скан (JPEG, PNG, WebP), цифровой PDF, текст TXT и JSON из некоторых сервисов электронных чеков. Можно просто вставить текст чека.
2. Фото распознаётся локально в браузере модулем Tesseract.js с русским и английским языками. PDF сначала читается как текст через PDF.js, а страницы-изображения направляются в OCR. Библиотеки и языковые данные загружаются из CDN **только по запросу**, требуют интернета при первом запуске и могут оказаться недоступны у некоторых провайдеров.
3. На экране проверки видны распознанные позиции, предлагаемые связи с существующей закупкой или каталогом, количество, единицы и сумма. Сомнительные позиции по умолчанию не отмечены; все изменения требуют подтверждения.
4. Подтверждённые покупки добавляются в партии товаров. Связанные позиции в списке закупки уменьшаются или удаляются при полном приобретении; остальные остаются в списке. Нераспознанные позиции не считаются купленными.
5. Одинаковый распознанный чек защищён от повторного внесения по контрольному хешу. В локальных метаданных сохраняется короткая история импортов, но изображения чеков и их полный текст **не сохраняются в базе**.
6. Нельзя получить товарные позиции по одному QR-коду кассового чека без загрузки электронного фискального документа из внешнего источника, например через официальный сервис ФНС. QR содержит реквизиты для нахождения чека, но не товарный состав.
7. Распознавание фото не гарантирует правильность названия, количества или цены. Нужно обязательно сверять предложенные данные с бумажным либо электронным чеком. В v0.7 распознавание ограничено первыми четырьмя страницами PDF.
8. Локальная IndexedDB остаётся прежней (schema 1), ранее сохранённые запасы и резервные копии не мигрируются. Новые операции добавляются лишь после подтверждения.

**Ограничение:** пока нет автоматического получения чека из ФНС по QR-коду. Для наиболее надёжного результата используйте цифровой PDF или текстовый чек. OCR фотографий является экспериментальной функцией и может не загрузиться при отсутствии доступа к CDN.

## Тест исправления чеков v0.8

- Добавлен разбор товарных строк, в которых название, изготовитель, количество и сумма идут на разных строках (типично для скриншотов ВкусВилла и Магнита).
- Встроенная проверка на текстовой реконструкции двух реальных пользовательских чеков: 3 позиции ВкусВилла (247,82 ₽) и 8 позиций Магнита (1 071,65 ₽) успешно выделяются. Проверка **не доказывает**, что OCR на конкретном телефоне прочитает сами изображения без ошибок.
- Изображения увеличиваются в допустимых пределах, переводятся в градации серого и повышают контраст перед локальным OCR.
- В окне проверки чека доступно «Показать исходный распознанный текст» и «Сохранить отчёт распознавания». Отчёт JSON экспортируется **только на устройстве**, без отправки в GitHub. Он содержит полученный OCR-текст, названия и суммы, поэтому при передаче файла третьим лицам учитывайте конфиденциальность.
- Уже проведённые закупки и сохранённые партии **не редактируются задним числом**. Для исследования ошибок ранее загруженного чека экспортируйте основную резервную копию JSON или пришлите снимок экрана результата.
- Единицы «кг» и «шт.» не преобразуются автоматически. Если название из чека совпадает с закупкой, но единицы отличаются, необходимо явно согласовать учёт вручную.

## Исправление локального OCR, версия 0.9

- Причина ошибки «Не удалось загрузить библиотеку (интернет или CDN)»: Tesseract.js был привязан к внешнему сервису jsDelivr.
- OCR-движок (Tesseract.js 5.1.1), Web Worker, четыре варианта Tesseract Core/WebAssembly, две обученные языковые модели (rus, eng) и PDF.js теперь размещены в `vendor/ocr/` этого репозитория.
- Распознавание продолжает работать внутри браузера; фото не загружаются на сторонние серверы. При первом использовании необходимо скачать файлы движка (включая языковые модели), поэтому может потребоваться время и интернет.
- Нет обязательной зависимости от внешнего CDN для фото- и PDF-распознавания. Обычный текстовый импорт работает без OCR.
- Содержимое IndexedDB, товары и существующие резервные копии не менялись (schema 1).
- OCR исправлен технически, но качество на конкретном устройстве и корректность обработки изображений требуют пользовательского теста после публикации.
- Исходный код и лицензии всех используемых сторонних модулей сохраняются рядом с пакетами (см. файлы LICENSE в `vendor/ocr/`).
